End-to-end walkthrough: run a LightEval evaluation locally with EvalHub, MLflow experiment tracking, and OCI artifact storage — no Kubernetes required.

This tutorial uses the [LightEval adapter](https://github.com/eval-hub/eval-hub-contrib/tree/main/adapters/lighteval) from eval-hub-contrib. For background on how local mode works, see the [Local Mode guide](/guides/local-mode/).

## Prerequisites

Install the following tools before starting:

- [uv](https://docs.astral.sh/uv/) — Python package manager
- [podman](https://podman.io/) (or Docker) — for running the OCI registry
- [ORAS](https://oras.land/docs/installation) and `jq` — for inspecting OCI artifacts and job responses
- [ollama](https://ollama.com/) (or any OpenAI-compatible LLM server) — for serving a local model

## Setup

<Steps>

1. **Create the project directory and virtual environment**

   ```bash
   mkdir local-lighteval && cd local-lighteval
   uv venv --python 3.12
   ```

   :::tip
   Whenever the tutorial asks you to open or use another terminal, activate the virtual environment first with `source .venv/bin/activate`, or prefix commands with `uv run` if not activating the venv — even when not explicitly mentioned.
   :::

2. **Download the LightEval adapter**

   Download the adapter, its helper modules, and its requirements from eval-hub-contrib.

   ```bash
   adapter_url=https://raw.githubusercontent.com/eval-hub/eval-hub-contrib/main/adapters/lighteval
   for file in main.py _hf_offline.py custom_tasks.py lighteval_logprob_patch.py \
       lighteval_memory_cap.py requirements.txt requirements-overrides.txt; do
     curl -fsSLO "$adapter_url/$file"
   done
   ```

3. **Install dependencies**

   Install the CLI and adapter requirements. The SDK's `server` extra installs
   the `eval-hub-server` package. The install requires version 1.1.0 or later
   of both packages for job-level OCI publication.

   ```bash
   printf '%s\n' \
     'eval-hub-sdk[adapter,core,server,cli]>=1.1.0' \
     'eval-hub-server>=1.1.0' > sdk-version.txt
   uv pip install -r requirements.txt \
     --override requirements-overrides.txt --override sdk-version.txt
   ```

4. **Start MLflow (optional)**

   Only needed if you want experiment tracking. Skip this step if you just want to run evaluations.

   Install MLflow and start the server:

   ```bash
   uv pip install "mlflow>=3.11"
   ```

   :::note
   The first `mlflow server` start may take a few extra seconds while it initialises the database.
   :::

   ```bash
   source .venv/bin/activate

   mlflow server \
     --backend-store-uri sqlite:///mlflow.db \
     --host localhost \
     --port 5000
   ```

   Verify from another terminal:

   ```bash
   curl http://localhost:5000/health
   ```

   The MLflow UI dashboard is accessible at `http://localhost:5000`.

5. **Start the OCI registry (optional)**

   Only needed if you want to persist evaluation artifacts to an OCI registry. Skip this step if you just want to run evaluations.

   In another terminal, pull the registry image and start it at `http://localhost:5001`:

   ```bash
   podman pull docker.io/library/registry:2

   podman run -d -p 5001:5000 \
       --name eval-hub-oci-registry \
       -e REGISTRY_STORAGE_DELETE_ENABLED=true \
       docker.io/library/registry:2
   ```

6. **Start the LLM server**

   Pull a model:

   ```bash
   ollama pull llama3.2:3b-instruct-q4_K_M
   ```

   Verify it's running:

   ```bash
   curl -s http://localhost:11434/v1/chat/completions \
     -H "Content-Type: application/json" \
     -d '{
       "model": "llama3.2:3b-instruct-q4_K_M",
       "messages": [{"role": "user", "content": "Why is the sky blue?"}],
       "max_tokens": 100
     }'
   ```

7. **Start the EvalHub server**

   Starting with eval-hub-sdk 1.0.3, Local mode starts a sidecar automatically.

   Start the packaged server with its built-in local defaults:

   ```bash
   evalhub server start
   ```

   You do not need to create or set `my-config.yaml` for the basic tutorial.

   If you enabled MLflow or need to customize other server settings, use a
   configuration file instead of the command above. For example, when using
   MLflow, configure `mlflow.tracking_uri`:

   ```yaml
   service:
     port: 8080

   database:
     driver: sqlite
     url: file::eval_hub:?mode=memory&cache=shared

   mlflow:
     tracking_uri: http://localhost:5000
   ```

   Set the configuration before starting the server:

   ```bash
   evalhub config set server_config_file my-config.yaml
   evalhub server start
   ```

   ```text
   Server started (PID 12345).
     URL:  http://localhost:8080
     Logs: ~/.config/evalhub/server/server.log
   ```

   Verify the server is healthy:

   ```bash
   evalhub config set base_url http://localhost:8080
   evalhub health
   ```

   ```text
   EvalHub service: healthy (2ms)
   ```

8. **Register the provider**

   Create a provider definition file `lighteval.yaml`:

   ```yaml
   name: lighteval
   description: LightEval adapter for evaluation framework
   runtime:
     local:
       command: "python main.py"
       env:
         - name: MLFLOW_TRACKING_URI
           value: http://localhost:5000
         - name: OCI_INSECURE
           value: "true"
   benchmarks:
     - id: gsm8k
       name: Grade-school math word problems
       description: |-
         Multi-step arithmetic word problems requiring 2-8 reasoning steps
         (8-shot, 1,319 examples).
       category: math
       metrics:
         - exact_match
         - acc
       num_few_shot: 8
       dataset_size: 1319
       tags:
         - math
         - reasoning
         - lighteval
       primary_score:
         metric: acc
         lower_is_better: false
       pass_criteria:
         threshold: 0.25
   ```

   Register it with the CLI:

   ```bash
   evalhub providers create --file lighteval.yaml
   ```

   ```text
   Provider created: 38f7bdba-3fe0-4a68-8ef9-4220faff771f
   ```

   Save the provider ID for subsequent commands (your ID will differ):

   ```bash
   PROVIDER_ID="38f7bdba-3fe0-4a68-8ef9-4220faff771f"
   ```

   See the [Local Mode guide — Provider Configuration](/guides/local-mode/#provider-configuration-for-local-mode) for details on the `runtime.local` section.

   Verify the provider was registered:

   ```bash
   evalhub providers list
   ```


   Query the provider's available benchmarks:


   :::note

## Run an evaluation

With all services running, submit a job using the CLI:

```bash
evalhub eval run \
  --name my-eval-job \
  --model-url http://localhost:11434/v1 \
  --model-name llama3.2:3b-instruct-q4_K_M \
  --provider $PROVIDER_ID \
  --benchmark $BENCHMARK_ID \
  --param num_examples=10 \
  --param num_few_shot=0 \
  --wait
```

Save the job ID from the output and check results:

```bash
JOB_ID="<job-id-from-output>"
evalhub eval results $JOB_ID
```


### With MLflow experiments and OCI artifact storage

The evaluation card and bundle steps require `eval-hub-server` 1.1.0 or later.
If you started MLflow and the OCI registry in the setup steps, add both
`--experiment` and the `--oci-*` flags. To run with only OCI export, omit
`--experiment`.

```bash
evalhub eval run \
  --name my-eval-job \
  --model-url http://localhost:11434/v1 \
  --model-name llama3.2:3b-instruct-q4_K_M \
  --provider $PROVIDER_ID \
  --benchmark $BENCHMARK_ID \
  --param num_examples=10 \
  --param num_few_shot=0 \
  --experiment my-local-experiment \
  --oci-host http://localhost:5001 \
  --oci-repository local-eval-results \
  --wait
```

Example output:

### Fetch the evaluation bundle from the local registry

<Since version="1.1.0" />

After the evaluation finishes, [check OCI publication with `eval status`](/guides/cli/#check-oci-publication-with-eval-status).
Once OCI publication reaches `completed`, fetch the bundle index using the
returned digest-qualified reference.

```bash
bundle_ref=$(evalhub eval status "$JOB_ID" --format json |
  jq -er '.[0].results.oci.evaluation_bundle.oci_reference') &&
  oras manifest fetch --plain-http --pretty "$bundle_ref"
```

The output is an OCI image index. The first `manifests` entry points to the
evaluation card manifest, whose layer contains the job summary JSON. The
following entries point to the completed benchmark artifacts in benchmark
order. In this example the second entry's digest matches the `oci_digest`
in the benchmark results above. See [OCI export results](/guides/results-and-scoring/#oci-export-results) for details.

## What's running

After completing setup, you have the EvalHub server, its automatically managed sidecar, and the model server running. MLflow and the OCI registry are also running if you enabled those optional setup steps:

| Service | URL | Purpose |
|---|---|---|
| **EvalHub server** (`evalhub server`) | `http://localhost:8080` | Evaluation orchestration |
| **Sidecar** | Managed automatically by Local mode | Supports Local mode evaluation traffic |
| **MLflow** | `http://localhost:5000` | Experiment tracking dashboard |
| **OCI registry** | `http://localhost:5001` | Artifact storage |
| **Ollama** | `http://localhost:11434` | LLM inference |
